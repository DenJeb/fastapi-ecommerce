# 02 — 需求规格说明书（SRS）

## 1. 范围与优先级

优先级：P0 = 核心必做；P1 = 核心完成后做；P2 = 可选扩展。

### 1.1 用户与权限

| ID | 需求 | 优先级 | 验收要点 |
|---|---|---:|---|
| AUTH-01 | 用户注册 | P0 | 邮箱/用户名唯一；密码安全哈希存储 |
| AUTH-02 | 用户登录并获得访问令牌 | P0 | 凭据错误返回统一错误；令牌过期可识别 |
| AUTH-03 | 获取当前用户信息 | P0 | 只能返回当前身份信息 |
| AUTH-04 | 管理员角色授权 | P0 | 普通用户不能调用管理接口 |
| AUTH-05 | 刷新令牌/登出 | P1 | 若实现 refresh token，需明确撤销策略 |

### 1.2 商品目录

| ID | 需求 | 优先级 | 验收要点 |
|---|---|---:|---|
| CAT-01 | 创建、修改、上下架商品 | P0 | 仅管理员；状态规则明确 |
| CAT-02 | 分类创建与层级管理 | P0 | 禁止形成循环父子关系 |
| CAT-03 | 商品列表、详情、分页筛选 | P0 | 只向普通用户展示可售商品 |
| CAT-04 | 商品变体/SKU 管理 | P0 | SKU 唯一；价格与库存归属于 SKU |
| CAT-05 | 商品图片/媒体管理 | P2 | 第一版可仅保存 URL 或文件元数据 |

### 1.3 库存

| ID | 需求 | 优先级 | 验收要点 |
|---|---|---:|---|
| INV-01 | 管理员调整现有库存 | P0 | 每次调整写库存流水并记录原因 |
| INV-02 | 查询 SKU 可售库存 | P0 | available = on_hand - reserved |
| INV-03 | 下单时预留库存 | P0 | 不允许预留后可售库存为负 |
| INV-04 | 支付成功后确认扣减 | P0 | 预留转为已售出，数量变化可追溯 |
| INV-05 | 订单取消/超时释放预留 | P0 | 释放操作幂等 |
| INV-06 | 库存预警 | P2 | 可后续增加低库存阈值 |

### 1.4 购物车与结算

| ID | 需求 | 优先级 | 验收要点 |
|---|---|---:|---|
| CART-01 | 用户添加 SKU 到购物车 | P0 | 数量必须为正整数 |
| CART-02 | 修改/删除购物车项 | P0 | 只能修改自己的购物车 |
| CART-03 | 获取购物车及实时商品价格 | P0 | 价格以服务端当前数据为准 |
| CHECK-01 | 预览结算金额 | P0 | 校验商品状态、库存、优惠券 |
| CHECK-02 | 创建订单 | P0 | 服务端重新计算价格；原子预留库存 |
| CHECK-03 | 防止重复提交 | P1 | 使用幂等键或业务唯一约束 |

### 1.5 订单与支付

| ID | 需求 | 优先级 | 验收要点 |
|---|---|---:|---|
| ORD-01 | 创建订单及订单明细快照 | P0 | 保存下单时商品名、SKU、单价、数量 |
| ORD-02 | 用户查询自己的订单 | P0 | 越权访问按统一策略拒绝 |
| ORD-03 | 管理员查询与更新订单 | P0 | 只允许合法状态迁移 |
| ORD-04 | 用户取消未支付订单 | P0 | 取消后释放库存 |
| PAY-01 | 发起模拟支付 | P0 | 生成支付记录，不接真实网关 |
| PAY-02 | 模拟支付成功/失败 | P0 | 同一支付结果重复提交不重复记账 |
| PAY-03 | 退款记录 | P1 | 仅允许满足规则的已支付订单退款 |

### 1.6 优惠券

| ID | 需求 | 优先级 | 验收要点 |
|---|---|---:|---|
| PROMO-01 | 管理员创建优惠券 | P1 | 有效期、门槛、总量、每人限领规则 |
| PROMO-02 | 用户领取/使用优惠券 | P1 | 不得超发、重复核销 |
| PROMO-03 | 结算时计算优惠 | P1 | 服务端计算；订单保存优惠快照 |

## 2. 业务规则

### 2.1 金额
- 使用 `DECIMAL` 存储金额，禁止使用浮点数进行金额计算。
- API 金额统一使用十进制字符串或明确的 decimal JSON 表示约定。
- 商品单价、优惠金额、运费（若后续增加）、订单应付金额由服务端计算。
- 订单明细保存下单时商品名称、SKU、单价和数量快照。

### 2.2 库存
- `on_hand`：仓库当前实物库存。
- `reserved`：已为未完成订单预留的库存。
- `available = on_hand - reserved`。
- 预留时要求 `on_hand - reserved >= requested_quantity`。
- 支付成功：`on_hand -= qty` 且 `reserved -= qty`。
- 取消/超时：`reserved -= qty`。
- 所有库存变更必须在事务中完成并写入流水。

### 2.3 订单
- 订单至少包含一个订单明细。
- 订单金额以创建订单时的价格快照为准。
- 用户只能取消未支付订单；已支付订单走退款流程。
- 订单状态迁移必须经过领域服务校验，不允许任意写状态字段。

### 2.4 支付
- 支付是模拟流程，状态包括 `PENDING`、`SUCCEEDED`、`FAILED`、`REFUNDED`。
- 支付成功与库存确认、订单状态更新必须保证一致性。
- 支付回调/模拟结果处理必须幂等。

### 2.5 优惠券（P1）
- 优惠券必须在有效期内，且满足最低消费门槛。
- 使用次数不得超过总量或用户限额。
- 订单取消/退款是否返还优惠券需明确；第一版建议取消未支付订单时释放占用，已支付退款不自动返券，除非专门实现规则。

## 3. 非功能需求

| 类别 | 要求 |
|---|---|
| 安全 | 密码哈希；认证与授权；输入验证；不泄露堆栈 |
| 一致性 | 库存、订单、支付核心写操作具备事务边界 |
| 可维护性 | 模块边界清晰；配置与业务代码分离 |
| 可测试性 | 关键服务可单测；API 可集成测试 |
| 可观测性 | 统一日志格式、请求 ID、异常日志 |
| 性能 | 第一版不设高并发 SLA；先保证正确性 |
| 可移植性 | 本地开发环境可通过文档复现 |

## 4. 暂缓需求

多仓库分配、渠道定价、多币种、复杂促销叠加、税务、物流、真实支付、退款自动化、全文搜索、消息队列、微服务等均不进入 P0。
