# 01 — 项目说明书（Project Brief）

## 1. 项目名称

Saleor-inspired Commerce Backend：基于 FastAPI 的模块化电商后端学习项目。

## 2. 项目背景

通过研究 Saleor 等成熟开源电商系统的领域模型与业务流程，独立设计并实现一个规模可控的电商后端。项目重点不是复刻 Saleor 的全部能力，而是理解商品、SKU、库存、购物车/结算、订单、优惠与支付等业务如何协作。

## 3. 项目目标

完成后应能够证明开发者可以：

- 使用 FastAPI 设计清晰、版本化的 REST API。
- 使用 MySQL 与 SQLAlchemy 2.x 建模关系型业务数据。
- 使用 Alembic 管理数据库 schema 迁移。
- 实现认证、授权、业务校验与统一异常处理。
- 正确处理订单创建、库存预留/扣减/释放、优惠券核销等业务规则。
- 使用事务、唯一约束、行级锁或条件更新保护关键数据。
- 编写单元测试、集成测试与关键业务场景测试。
- 在本地通过 Docker Compose 启动应用及依赖服务（工程化阶段）。

## 4. 非目标（明确不做）

- 不做完整电商前端或管理后台 UI。
- 不接入真实支付渠道；支付仅模拟成功、失败、超时等结果。
- 不接入真实物流、短信、邮件服务。
- 不实现多渠道、多币种、多语言、多仓库。
- 不实现复杂税务、跨境结算、Marketplace 多卖家分账。
- 不以微服务拆分为目标；先采用模块化单体。
- 不以公网生产上线、高可用、商业运营为验收目标。
- 暂不加入 LLM、RAG、Agent 等 AI 功能。

## 5. 用户角色

| 角色 | 能力概述 |
|---|---|
| 游客 | 浏览已上架商品；可创建访客购物车（是否启用由实现阶段决定） |
| 注册用户 | 管理个人资料、购物车、地址、订单；提交结算 |
| 管理员 | 管理商品、分类、SKU、库存、优惠券、订单 |
| 系统任务 | 处理过期库存预留/未支付订单超时（后续阶段） |

第一版为控制范围，购物车建议绑定登录用户；访客购物车可列为扩展。

## 6. 核心业务范围

- 身份认证与角色权限
- 商品、分类、商品变体（SKU）
- 单仓库库存与库存流水
- 购物车与结算
- 订单与订单明细
- 模拟支付与退款记录
- 优惠券（固定金额或百分比，择一或两种）
- 管理员操作审计（轻量）

## 7. 成功标准

- 核心业务可通过 API 完整演示。
- 数据库结构有 ERD、约束与索引说明。
- 订单金额由服务端计算，不信任客户端提交总价。
- 并发下单不会造成库存负数。
- 未授权用户无法访问他人购物车、地址与订单。
- 关键业务路径有自动化测试。
- README 能说明如何配置、迁移、启动和测试。

## 8. 设计原则

1. 业务正确性优先于技术组件数量。
2. 模块化单体优先于过早微服务化。
3. 先完成同步核心流程，再引入 Redis / 后台任务。
4. 关键状态变化必须有显式状态机与测试。
5. 不为了“用技术”而添加没有业务理由的组件。
