# 07 — 测试计划与验收标准

## 1. 测试层次

| 层级 | 范围 | 示例 |
|---|---|---|
| Unit | 不依赖真实 DB 的领域规则 | 订单状态迁移、优惠计算 |
| Integration | MySQL/Redis 等依赖 | 事务回滚、唯一约束、库存并发 |
| API | HTTP 行为与权限 | 登录、越权、错误响应 |
| Regression | 修复过的 bug | 重复支付、取消订单竞态 |

关键业务集成测试应使用与开发环境一致的 MySQL/InnoDB 行为；不要只用 SQLite 替代后就认为验证了 MySQL 锁与事务语义。

## 2. 核心验收用例

### Auth / Authorization
- [ ] 注册时重复 email / username 被拒绝。
- [ ] 密码以安全哈希存储，响应不含 hash。
- [ ] 未认证访问受保护接口返回 401。
- [ ] 普通用户访问管理员接口返回 403。
- [ ] 用户 A 不能读取或修改用户 B 的购物车、地址、订单。

### Catalog
- [ ] 非管理员不能创建或修改商品。
- [ ] SKU 唯一约束生效。
- [ ] 下架商品不出现在普通商品列表。
- [ ] 分页边界、非法排序字段得到正确处理。

### Inventory
- [ ] 入库、盘亏产生正确流水。
- [ ] 不能把实物库存调整到低于已预留量。
- [ ] 库存不足时下单失败且不产生订单/预留残留。
- [ ] 两个并发请求争抢最后一件商品，最多一个成功。
- [ ] 支付成功后 on_hand 与 reserved 正确变化。
- [ ] 取消订单后预留释放且不会重复释放。

### Orders / Payments
- [ ] 订单明细保存商品/SKU/价格快照。
- [ ] 客户端篡改总价不会影响服务端计算结果。
- [ ] 用户只能取消待支付订单。
- [ ] 重复支付成功请求不会重复扣库存或重复更新订单。
- [ ] 支付失败不会把订单标记为已支付。
- [ ] 退款金额不能超过可退金额。
- [ ] 非法状态迁移被拒绝并保留原状态。

### Promotions
- [ ] 未生效/过期优惠券不可使用。
- [ ] 不满足门槛不可使用。
- [ ] 并发领取最后一张优惠券不能超发。
- [ ] 同一用户不能超过每人限额。

## 3. 完成定义（Definition of Done）

一个功能只有同时满足以下条件才算完成：
1. 需求与业务规则已写清楚。
2. API 请求/响应和错误行为符合约定。
3. 数据库约束、事务边界正确。
4. 正常路径与至少一个失败路径有测试。
5. 权限校验经过验证。
6. 文档已更新。
7. 代码通过格式/静态检查（项目选定工具后补充）。

## 4. 建议的测试数据

准备固定的测试工厂：
- 1 个管理员
- 2 个普通用户
- 2 个分类
- 3 个商品
- 5 个 SKU
- 库存分别为 0、1、10
- 1 张有效优惠券、1 张过期优惠券、1 张限量优惠券

测试必须可重复执行，不依赖手工修改数据库状态。
